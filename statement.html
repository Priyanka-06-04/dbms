Statement-level trigger

A statement-level trigger is fired once on behalf of the triggering statement, regardles of the number of rows in the table that the triggering statement affects (even if no rows ate affected).

For example, if a DELETE statement deletes several rows from a table, a statement-level DELETE trigger is fired only once, regardless of how many rows are deleted from the table.

However, statement-level triggers cannot be used to access the data that is being inserted, updated or deleted. In other words, they do not have access to keywords new and old, which are used to access data. Statement-level triggers are useful if the code in the trigger action does not depend on the data provided by the triggering statement or the rows affected.

Syntax for a Statement-level trigger is:

CREATE OR REPLACE TRIGGER < trigger_name>
‹BEFORE | AFTER> [ACTION] [OR [ACTION] OR [ACTION>]
ON < table_name>
DECLARE
[variable definitions]
BEGIN
[trigger_code]
EXCEPTION
[exception clauses]
END [trigger_name];

Example

            
SQL> CREATE OR REPLACE TRIGGER STATEMENT_LEVEL
BEFORE UPDATE ON EMP
DECLARE
MSG VARCHAR2(30):= 'STATEMENT-LEVEL TRIGGER FIRED':
BEGIN
DBMS_OUTPUT -PUT_LINE(MSG) ;
END;
Trigger created.
SQL> UPDATE EMP
SET SAL=11000
WHERE DEPTNO=30;
STATEMENT-LEVEL TRIGGER FIRED
6 rows updated
